M04 curator review and guarded publication — September 20, 2026

Scope
- Added a small custom artifact-review state machine. This is not Sanity Workflows or Content Releases integration.
- Reviews are separate public-safe artifactReview documents.
- Studio actions support submit, request changes with a required reason, resubmit after revision, approve the submitted revision, and guarded publish.
- Only the built-in artifact Publish action is replaced; other document actions and non-artifact document types are preserved.

Subagent use
- Two read-only subagents inspected installed Sanity 6.15.0 APIs and produced the transition/acceptance specification.
- One bounded Codex gpt-5.5 builder implemented the first pass without permission to commit, deploy, publish, or mutate the dataset.
- Main-session integration review found and repaired two issues not caught by the builder: stale-draft decisions compared the stored revision to itself, and cleared review fields could be written as undefined instead of explicit unsets.

TDD evidence
- Builder RED: the initial focused workflow test failed before src/domain/artifact-review.ts existed.
- Main-session regression RED: 4 of 12 focused tests failed, reproducing submit bypass and stale-draft decision bugs.
- GREEN: 12/12 focused workflow tests passed after repair.

Known limitations
- The custom actions are Studio UI policy, not a raw Content Lake authorization boundary.
- Sufficiently privileged administrators or API clients can bypass the workflow.
- The final read-before-publish check has a small check-to-publish race because the installed built-in publish operation does not accept a draft revision precondition.
- Review metadata is public and must remain public-safe.
